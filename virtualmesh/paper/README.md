## MVP (Track C) — assemble the passing pieces into a runnable demo
- Take 4-8 frozen specialist models (frame-connected: shared base or embedding anchor).
- Implement: frame alignment (relative-reps/anchors) -> coupled settling (DEQ-style fixed point) ->
  MZ low-rank routing index (from G2) -> decode. Add distilled transitive edges (from G3) if G3 passes.
- Demo: answer a split-knowledge query the virtual mesh gets right that no single model / pooling does.
- Keep it minimal and honest: the MVP shows the mechanism on real models; it is NOT the formal machinery.
- If a gate reds, the MVP omits that capability and the demo scope shrinks accordingly. No faking.

## Merge protocol (after gates return)
For each gate: PASS -> promote claim into spec (as validated law) + paper (as result) + MVP (as feature).
FAIL -> drop from spec, report as characterized negative in paper, omit from MVP. The paper's final
claims = intersection of (formally specified) and (gate-validated). Nothing formalized that isn't measured.
