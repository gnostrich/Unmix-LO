# PRE-REGISTRATION — first REAL-model streams through the io_trace reader (frozen before run code)

The validated instrument (`io_trace/stream_trace.py`, UNCHANGED) pointed at streams generated by running real
frozen models ourselves — provenance clean by construction (we control the inputs; nothing scraped). CPU-sized
models proven runnable earlier in this session. The reader is fit-free: memory sequence = input–output
cross-correlation; atoms = Hankel singular values above the permutation-null floor; poles = Ho-Kalman.

## The three real streams
1. **MiniLM, memoryless by construction** (real zero-control): input u_t = white 3-dim noise, rendered as a
   sentence ("sensor a=.. b=.. c=.."); output y_t = MiniLM embedding of THAT sentence alone (projected to a
   fixed 8-dim channel basis — a linear output projection, disclosed; projection cannot create memory).
   **Frozen prediction: order 0** (the reader must not fabricate memory from a real stateless encoder).
2. **MiniLM, sliding window W=4** (real finite-memory control): identical, except the sentence contains the
   CURRENT and the LAST 3 inputs. The model is still stateless — the memory lives in the windowed I/O
   interface, which is exactly what the reader sees. **Frozen predictions: (a) order > 0; (b) the memory
   response |ĥ_k| sits above the floor for lags 1..3 and falls to the floor for k ≥ 4 — the read cutoff must
   match the constructed window edge.**
3. **Qwen2.5-0.5B, token stream** (the open question): feed sequences of random digit tokens; u_t = the digit
   at position t (scalar, centered); y_t = the last-layer hidden state at position t (fixed 8-dim projection).
   The transformer attends over its whole context, so its I/O memory could be anything from a few effective
   modes to no clean termination. **Exploratory — no frozen prediction beyond honesty**: report order, memory
   decay, and gap; a low clean order (atomic) would be a surprising positive and gets extra scrutiny (seed
   variation) before being believed.
